ARCHITECTURE:
-------------
The system uses a multi-tier architecture with privilege separation:

    Browser
       ↓ HTTP
    PHP Web Application (runs as www-data - low privilege)
       ↓ exec() with sudo
    Bash Scripts (runs as root - high privilege)
       ↓ Read/Write
    User Data Files (stores password hashes in text files)

WHY THIS DESIGN?
- Security: Web layer can't directly access password hashes
- Separation: Clear boundary between UI and authentication
- Flexibility: Easy to audit backend scripts independently

LOGIN FLOW (3 STEPS):
---------------------
1. USERNAME ENTRY
   - User enters username
   - Regex validation: /^[[:alnum:]][-|\.|_[:alnum:]]{0,28}[[:alnum:]]$/
   - Stored in $_SESSION['login']['username']

2. PASSWORD ENTRY
   - Backend fetches salt and hash method (v-get-user-salt)
   - PHP hashes password using the method (MD5/SHA-512/yescrypt/DES)
   - Backend verifies hash (v-check-user-hash)
   - Additional checks: login disabled, IP whitelist

3. TWO-FACTOR AUTHENTICATION (if enabled)
   - User enters 6-digit TOTP code
   - Backend verifies (v-check-user-2fa)
   - Session created on success

SECURITY FEATURES (10+):
------------------------
1. CSRF Protection - Token on every form
2. Session Timeout - Configurable inactivity timeout
3. IP Verification - Tracks user IP, prevents hijacking
4. Brute Force - 2-second delay on failed login
5. Password Hashing - yescrypt/SHA-512/MD5/DES
6. Two-Factor Auth - TOTP support
7. Session Regeneration - After login (prevents fixation)
8. Comprehensive Logging - All auth events logged
9. IP Whitelisting - Per-user allowed IPs
10. Login Disable - Per-user login lock

PASSWORD HASHING:
-----------------
Supports 4 algorithms (for compatibility):

1. Yescrypt (RECOMMENDED)
   - Format: $y$j9T$salt$hash...
   - Most secure, modern algorithm
   - Password passed via temp file (secure)

2. SHA-512
   - Format: $6$rounds=5000$salt$hash...
   - Good security, widely used

3. MD5 (LEGACY)
   - Format: $1$salt$hash...
   - Acceptable but aging

4. DES (VERY OLD)
   - Format: 2-char salt + 11-char hash
   - Weak, not recommended

SESSION MANAGEMENT:
-------------------
Key session variables:
- $_SESSION['user'] - Logged-in username
- $_SESSION['token'] - CSRF token (regenerated)
- $_SESSION['userContext'] - Role (admin/user)
- $_SESSION['LAST_ACTIVITY'] - For timeout tracking
- $_SESSION['look'] - Impersonated user (admin only)

Session lifecycle:
1. session_start() on every page
2. User logs in → variables set
3. session_regenerate_id() after login
4. Timeout/logout → destroy_sessions()

USER ROLES:
-----------
ADMIN:
- Can see all users
- Can impersonate other users
- Lands on /list/user/

REGULAR USER:
- Limited to own account
- Lands on first available feature page
- Feature priority: Web > DNS > Mail > DB > Cron > Backup

================================================================================
                      RECOMMENDATIONS FOR REWRITE
================================================================================

CURRENT STACK:
--------------
Frontend: PHP 7.4+ with sessions
Backend: Bash scripts via exec()
Storage: Text files
Communication: JSON via shell commands
Hashing: crypt() with multiple methods

RECOMMENDED MODERN STACK:
-------------------------
Frontend: PHP 8.2+ or Node.js/TypeScript
Backend: Native PHP or REST API
Storage: PostgreSQL or MySQL
Communication: Database queries or HTTP API
Hashing: password_hash() with PASSWORD_ARGON2ID

WHAT TO KEEP:
-------------
✓ Multi-step authentication flow
✓ CSRF protection (critical)
✓ Session regeneration after login
✓ Comprehensive logging
✓ Two-factor authentication
✓ Role-based access control
✓ IP tracking (configurable)
✓ Session timeout

WHAT TO IMPROVE:
----------------
→ Replace exec() calls with native code
→ Use database instead of flat files
→ Add rate limiting (Redis/Memcached)
→ Add account lockout after X failures
→ Implement OAuth2/OpenID Connect
→ Add WebAuthn/FIDO2 support
→ Better error handling and logging
→ Email/SMS notifications for login events
→ Remember device functionality
→ Passwordless authentication options

MODERN ALTERNATIVES:
--------------------
Instead of:
    exec('v-check-user-hash admin /tmp/hash 192.168.1.1')

Use:
    password_verify($password, $user->password_hash)

Instead of:
    $hash = crypt($password, '$6$rounds=5000$' . $salt . '$')

Use:
    $hash = password_hash($password, PASSWORD_ARGON2ID)

CSRF TOKEN GENERATION:
----------------------
$token = bin2hex(random_bytes(16));
$_SESSION['token'] = $token;

CSRF VERIFICATION:
------------------
if ($method['token'] !== $_SESSION['token']) {
    header('Location: /login/');
    die();
}

PASSWORD HASHING (MODERN):
--------------------------
// Hash
$hash = password_hash($password, PASSWORD_ARGON2ID);

// Verify
if (password_verify($password, $hash)) {
    // Success
}

SESSION CREATION:
-----------------

}
